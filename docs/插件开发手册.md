# Plugin-Manual — RuleCraft 插件开发手册

RuleCraft 支持两种插件体系：**内置插件**（Go 代码编译入主程序）和 **JSON 规则插件**（通过 JSON 配置 + 外部脚本扩展）。本文档分别说明两者的开发方法。

## 1. 插件架构概述

```
规则引擎
  │
  ├── 内置插件（Layer 1）—— 编译入主程序
  │   ├── InputPlugin 接口     ← 26 个传感器
  │   └── OutputPlugin 接口    ← 20 个执行器
  │
  ├── JSON 规则插件（Layer 2）—— 外部脚本
  │   ├── rule.json            ← 插件元信息
  │   ├── {task_id}.conf       ← 任务配置
  │   └── .ps1 / .bat / .exe  ← 可执行脚本
  │
  └── 插件市场（Layer 3）—— 远程仓库
      └── Git 仓库中的插件目录
```

**选择指南：**

| 场景 | 推荐方式 |
|:-----|:---------|
| 需要直接调用 Win32 API | 内置插件 |
| 性能要求高（轮询场景） | 内置插件 |
| 用户自定义数据处理逻辑 | JSON 规则插件 |
| 需要与第三方服务交互 | JSON 规则插件 |
| 社区分享插件 | 插件市场 + JSON 规则插件 |

## 2. 内置输入插件开发

### 2.1 接口定义

```go
// plugin/interface.go
type InputPlugin interface {
    ID() string                              // 全局唯一标识符，如 "power"
    Name() string                            // 人类可读名称
    Collect(ctx *SystemContext) error         // 采集数据并写入 ctx.States
    IsAvailable() bool                       // 当前系统是否可用
}
```

### 2.2 SystemContext

```go
type SystemContext struct {
    Mu     sync.RWMutex
    States map[string]interface{}   // 全局状态存储
    Ctx    context.Context          // 支持超时取消
    Notify NotificationManager      // 通知管理器（可选）
}
```

**常用方法：**

| 方法 | 说明 |
|:-----|:------|
| `ctx.SetState(key, value)` | 写入全局状态 |
| `ctx.GetState(key)` | 读取全局状态 |
| `ctx.GetStateString(key)` | 读取字符串状态 |

### 2.3 完整示例

创建一个 `input/battery_input.go`：

```go
package input

import (
    "rulecraft/platform"
    "rulecraft/plugin"
)

type BatteryInput struct {
    plat platform.Platform
}

func NewBatteryInput(plat platform.Platform) *BatteryInput {
    return &BatteryInput{plat: plat}
}

func (b *BatteryInput) ID() string        { return "battery" }
func (b *BatteryInput) Name() string      { return "电池传感器" }
func (b *BatteryInput) IsAvailable() bool { return true }

func (b *BatteryInput) Collect(ctx *plugin.SystemContext) error {
    info, err := b.plat.CollectPowerInfo()
    if err != nil {
        if platform.IsErrNotImplemented(err) {
            ctx.SetState("battery.percent", -1)
            return nil
        }
        return err
    }
    ctx.SetState("battery.percent", info.BatteryPercent)
    ctx.SetState("battery.is_charging", info.IsCharging)
    return nil
}
```

### 2.4 注册到引擎

在 `input/inputs.go` 的 `RegisterBuiltinInputs` 中添加一行：

```go
func RegisterBuiltinInputs(registry *plugin.Registry, plat platform.Platform) error {
    inputs := []plugin.InputPlugin{
        // ... 已有插件 ...
        NewBatteryInput(plat),   // ← 添加这一行
    }
    // ...
}
```

### 2.5 输入插件规范

| 字段 | 要求 |
|:-----|:------|
| 状态键命名 | `{plugin_id}.{field}`，如 `power.battery_percent` |
| 错误处理 | 平台调用失败时写入默认值而非报错 |
| ErrNotImplemented | 当前 OS 不支持时优雅降级 |
| 类型选择 | 布尔用 `bool`，百分比用 `float64`，名称用 `string` |

### 2.6 插件配置参数

部分输入插件需要额外的配置参数（如 URL、目标地址等），这些参数通过任务编辑器的「输入数据」中的 `params` 字段设置。支持配置的插件：

| 插件 ID | 参数 | 说明 |
|---------|------|------|
| `http_request` | `url`, `timeout` | HTTP 请求目标 URL 和超时秒数 |
| `network_detect` | `target`, `mode`, `port` | 检测目标地址、模式(ping/tcp/http)、端口 |
| `file_monitor` | `paths`, `recursive` | 监控路径（逗号分隔）和是否递归 |
| `http_in` | `port`, `auth_key` | 监听端口和鉴权密钥（在系统设置中配置） |
| `tcp_udp_in` | `port`, `proto`, `auth_key` | TCP/UDP 监听端口和协议 |
| `websocket_in` | `port`, `auth_key` | WebSocket 监听端口和鉴权密钥 |

## 3. 内置输出插件开发

### 3.1 接口定义

```go
type OutputPlugin interface {
    ID() string                              // 全局唯一标识符
    Name() string                            // 人类可读名称
    Execute(params map[string]interface{}) error  // 条件成立时执行
    Reset(params map[string]interface{}) error    // 条件恢复时撤销
    IsAvailable() bool                       // 当前系统是否可用
}
```

### 3.2 生命周期

| supports_execute | supports_reset | 行为 |
|:----------------:|:--------------:|:-----|
| true | false | 仅条件成立时执行，恢复时不操作 |
| true | true | 成立时执行，恢复时撤销 |

不支持 Reset 的插件返回 `plugin.ErrResetNotSupported`。

### 3.3 完整示例

创建一个 `output/screenshot_output.go`：

```go
package output

import (
    "fmt"
    "rulecraft/plugin"
)

type ScreenshotOutput struct {
    plat PlatformSubset
}

func NewScreenshotOutput(plat PlatformSubset) *ScreenshotOutput {
    return &ScreenshotOutput{plat: plat}
}

func (s *ScreenshotOutput) ID() string        { return "screenshot" }
func (s *ScreenshotOutput) Name() string      { return "截图保存" }
func (s *ScreenshotOutput) IsAvailable() bool { return true }

// Execute 保存截图。
// params: path (string, 必填): 保存路径
func (s *ScreenshotOutput) Execute(params map[string]interface{}) error {
    path, _ := params["path"].(string)
    if path == "" {
        return fmt.Errorf("screenshot: path is required")
    }
    // 截图逻辑...
    return nil
}

func (s *ScreenshotOutput) Reset(params map[string]interface{}) error {
    return plugin.ErrResetNotSupported
}
```

### 3.4 注册到引擎

在 `output/outputs.go` 的 `RegisterBuiltinOutputs` 中添加一行。

### 3.5 使用 PlatformSubset

输出插件不应直接依赖 `platform.Platform` 全部方法，而应使用 `PlatformSubset` 接口按需声明：

```go
type PlatformSubset interface {
    SetVolume(level int) error
    SetPowerScheme(scheme string) error
    // 只声明本插件需要的方法
}
```

## 4. JSON 规则插件开发

JSON 规则插件是 RuleCraft 的扩展机制，允许用户通过 JSON 配置 + 外部脚本定义自定义数据处理逻辑。

### 4.1 目录结构

```
rules/
├── {plugin_id}/              # 插件目录
│   ├── rule.json             # 插件定义文件（必选）
│   ├── {executable_file}     # 可执行程序（必选）
│   └── {task_id}.conf        # 任务配置（零个或多个）
```

### 4.2 rule.json 规范

```json
{
    "plugin_id": "text_processor",
    "name": "文本处理器",
    "version": "1.0.0",
    "author": "YourName",
    "description": "将输入文本转为小写",
    "direction": "input",
    "executable": {
        "type": "powershell",
        "path": "rules/text_processor/process.ps1"
    },
    "execution_policy": {
        "timeout_seconds": 30,
        "retry_on_failure": 1
    },
    "functions": {
        "to_lowercase": {
            "name": "转为小写",
            "description": "将输入字符串转为小写",
            "input_params": {
                "value": {
                    "type": "string",
                    "description": "输入文本",
                    "required": true
                }
            },
            "output": {
                "result": {
                    "type": "string",
                    "description": "小写转换结果"
                }
            }
        }
    }
}
```

| 字段 | 必填 | 说明 |
|:-----|:----:|:-----|
| `plugin_id` | ✅ | 全局唯一标识符，`[a-z][a-z0-9_-]+` |
| `direction` | ❌ | `input`（默认，数据处理）或 `output`（动作执行） |
| `executable.type` | ✅ | `powershell` / `batch` / `executable` |
| `executable.path` | ✅ | 可执行程序路径 |

### 4.3 {task_id}.conf 规范

```json
{
    "task_id": "task_001",
    "rule_id": "text_processor",
    "source": {
        "type": "from_state",
        "key": "wifi.ssid"
    },
    "pipeline": [
        {
            "function": "to_lowercase",
            "enabled": true,
            "params": {}
        }
    ],
    "output": {
        "mode": "write_state",
        "target_key": "processed.ssid"
    },
    "callback": {
        "on_success": { "action": "continue_rule_engine" },
        "on_failure": { "action": "use_original_value" }
    }
}
```

### 4.4 脚本 stdin/stdout 协议

引擎与外部脚本通过 stdin/stdout 的 JSON 管道通信。

**输入（stdin）：**

```json
{
    "function_id": "to_lowercase",
    "value": "My_WiFi_SSID",
    "params": {},
    "__task__": {
        "task_id": "task_001",
        "rule_id": "text_processor",
        "processor_id": "ssid_cleaner"
    }
}
```

**输出（stdout）：**

```json
{
    "value": "my_wifi_ssid"
}
```

**PowerShell 脚本示例：**

```powershell
param([Parameter(ValueFromPipeline=$true)]$inputJson)
$data = $inputJson | ConvertFrom-Json
$value = $data.value
$result = $value.ToLower()
Write-Output "{ ""value"": ""$result"" }"
```

**Batch 脚本示例：**

```batch
@echo off
set /p input=
echo %input% > temp.json
rem ... 处理逻辑 ...
echo {"value": "processed"}
```

### 4.5 输出型（direction=output）规则插件

输出型插件的 `rule.json` 需要声明：

```json
{
    "plugin_id": "email_sender",
    "direction": "output",
    "lifecycle": {
        "supports_execute": true,
        "supports_reset": false
    }
}
```

输出插件的 `source` 通常为 `from_stdin`，参数由主程序在触发时传入。

### 4.6 环境变量注入

引擎在调用外部脚本时自动设置以下环境变量：

| 环境变量 | 说明 |
|:---------|:-----|
| `AUTOMATION_TASK_ID` | 当前任务 ID |
| `AUTOMATION_TASK_NAME` | 当前任务名称 |
| `AUTOMATION_RULE_ID` | 当前规则 ID |
| `AUTOMATION_PROCESSOR_ID` | 当前处理器 ID |

### 4.7 安全约束

- 路径遍历防护：`executable.path` 禁止包含 `..`
- 超时强制终止：所有子进程受 `timeout_seconds` 约束
- PowerShell 强制追加 `-ExecutionPolicy Bypass`
- 参数中的敏感字段（`password`、`token`、`secret`、`key`）在日志中替换为 `****`

## 5. 插件市场发布

### 5.1 仓库结构

在 GitHub 或 Gitee 上创建插件仓库，目录结构如下：

```
your-plugin-repo/
├── Input_Plugins/             # 输入插件
│   └── my_sensor/
│       ├── rule.json
│       └── collect.ps1
│
└── Output_Plugins/            # 输出插件
    └── my_action/
        ├── rule.json
        └── execute.ps1
```

### 5.2 安装方式

在 RuleCraft Web UI 的"插件市场"页面，添加仓库 URL，然后一键安装：

```
https://github.com/your-name/your-plugin-repo
```

系统会自动从 `Input_Plugins/` 和 `Output_Plugins/` 目录扫描可用插件。

### 5.3 版本管理

`rule.json` 中的 `version` 字段遵循 SemVer 2.0.0 规范。引擎会缓存已安装的插件，不会自动覆盖。用户需要手动点击"更新"按钮。

## 6. 附录：插件接口参考

### InputPlugin 接口

```go
type InputPlugin interface {
    ID() string
    Name() string
    Collect(ctx *SystemContext) error
    IsAvailable() bool
}
```

### OutputPlugin 接口

```go
type OutputPlugin interface {
    ID() string
    Name() string
    Execute(params map[string]interface{}) error
    Reset(params map[string]interface{}) error
    IsAvailable() bool
}
```

### Platform 接口（供内置插件使用）

```go
type Platform interface {
    // 传感器
    CollectWiFiInfo() (*config.WiFiInfo, error)
    CollectPowerInfo() (*config.PowerInfo, error)
    CollectNetworkInfo() ([]config.NetworkAdapterInfo, error)
    ListProcesses() ([]config.ProcessInfo, error)
    GetForegroundWindowInfo() (*config.WindowInfo, error)
    GetIdleSeconds() (uint64, error)
    GetSystemResources() (*config.SysResInfo, error)
    GetDiskInfo(drive string) (*config.DiskInfo, error)
    GetSessionInfo() (*config.SessionInfo, error)
    // 执行器
    PreventSleep(prevent bool) error
    ExecuteProcess(cmd string, args []string, workingDir string, env map[string]string) (int, error)
    SetVolume(level int) error
    SetBrightness(level int) error
    ShowNotification(title, message string, level string) error
    LockWorkstation() error
    PowerAction(action string) error
    SetWallpaper(path string) error
    KillProcess(pid int) error
    SetPowerScheme(scheme string) error
    SetNetworkAdapter(name string, enabled bool) error
}
```
